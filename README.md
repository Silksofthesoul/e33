# E33 — Mimi Markov

Авторский эксперимент Silksofthesoul с цепями Маркова первого порядка. Самостоятельное SPA на HTML, CSS и JavaScript: обучение, генерация и хранение данных происходят в браузере пользователя. Express, API, общая база и внешние библиотеки не нужны.

## Запуск

В корне скачанного проекта:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте http://localhost:8080/. Можно раздавать эти же файлы любым статическим сервером, в том числе из подкаталога `/experiments/e33/`. Все пути относительные. Для ES-модулей требуется HTTP(S), а не `file://`. Устанавливать npm-пакеты для запуска не нужно.

## Использование и данные

1. Введите текст и нажмите «Обучить и создать». Каждый новый текст дополняет личную модель, повтор того же целого текста не учитывается снова.
2. «Ещё вариант» создаёт новую последовательность из 65 слов.
3. Текст в поле сохраняется автоматически; модель сохраняется после обучения. Обновление страницы восстанавливает их.
4. «Очистить мои данные» после подтверждения удаляет только ключ этого эксперимента.

При переходе от предварительного имени Mimi Markov к E33 ключ хранилища сохранён. На том же origin уже введённые данные останутся доступны.

Ключ localStorage: `silksofthesoul:mimi-markov:spa:v1`. Он хранит текущий текст, версию формата, слова, переходы, частоты и хеши обученных текстов. Полная история исходных документов отдельно не архивируется. Серверный корпус не импортируется: первый запуск начинается с пустой модели.

Данные не отправляются в сеть. В приложении нет fetch/XHR, телеметрии, CDN и POST-маршрутов; CSP запрещает сетевые соединения скриптов. Это не шифрование: localStorage доступен другим скриптам того же origin. Для изоляции от других экспериментов используйте отдельный origin. Origin включает протокол, имя хоста и порт; смена одного из них создаст другое хранилище. Данные не синхронизируются между устройствами. Очистка данных сайта или завершение приватной сессии может удалить их.

При запрете доступа к localStorage приложение явно сообщает, что работает только в памяти текущей вкладки. При переполнении хранилища прежняя сохранённая модель не заменяется, а введённый текст остаётся в поле. Повреждённые или неизвестные версии данных не перезаписываются автоматически.

При наличии Web Locks операции разных вкладок выполняются последовательно. Без Web Locks предусмотрена проверка изменения данных перед записью, но localStorage не предоставляет атомарный compare-and-swap: для одновременного обучения используйте одну вкладку.

## Авторский алгоритм

`assets/markov.js`: методы `parse`, `setChainEnd`, `setChainItem`, `setCurrentChain`, `generate` перенесены без изменений из согласованной версии `4cc51b2b9aa7eb5dfb7fdb2dc89d45bc60070c36`. Тест фиксирует SHA-256 текста каждого метода. Сохранены разбиение по пробельным символам, частоты, дедупликация целого текста и взвешенный выбор следующего слова. Алгоритм не заменён библиотекой и не «улучшен» при переносе.

Изменён только слой среды: вместо Node crypto используется совместимый браузерный SHA-1 для ключа дедупликации, вместо fs — отдельный адаптер localStorage. SHA-1 здесь не используется для защиты данных. Исходные свойства генератора сохранены: 65 слов не означают фиксированный размер в байтах, длинные слова остаются длинными. Ввод ограничен прежними 50 000 UTF-16 единицами; нагрузка теперь локальна для вкладки пользователя.

## Проверка и статическая сборка

С уже установленным Node.js 22+:

```sh
node --test tests/*.test.js
node scripts/build.js
```

Сборка лишь копирует `index.html` и `assets/` в `dist/`; она необязательна для самостоятельного запуска. Зависимостей нет. `private: true` в package.json запрещает случайную публикацию в npm и не определяет видимость GitHub-репозитория. Тесты проверяют неизменность алгоритма, SHA-1, дедупликацию, генерацию, сохранение, ошибки квоты и работу нескольких вкладок. Пользовательские данные тестам не нужны.

`preview.json` — точный список статических файлов для каталога. `Description.md` задаёт название Mimi Markov; текст описания оставлен автору. Идентификатор каталога — `e33`, метка — E33, адрес в оболочке сайта — `/?work=e33`. Исходники самостоятельны от сайта и не должны импортироваться в его frontend.
